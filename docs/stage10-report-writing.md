# Stage 10：证据约束的报告写作

## 审计结论

- `AnalysisTaskSpec.output_language` 已支持 `zh-CN` / `en`，旧任务默认英文。
  `TaskUnderstandingService` 根据输入语言设置默认值，显式语言要求优先。
  既有中文视图会把英文 `feature_description`、定位和套餐权益直接放入正文，
  因而语言字段贯穿存储不等于正文已中文化。
- `build_matrix` 从 repository 读取观察记录，重验身份、来源归属、快照哈希、
  原文引用、时间和事实值，保留冲突和研究缺口。写作不能取代这层验证。
- `build_findings` 生成受限比较。`CompetitiveSynthesisProvider` 只返回已有
  Finding ID，负责排序，不负责自由写作，也不证明语言质量。
- 旧视图的矩阵与差异章节重复 `feature_description`，结论主要是通用边界说明。
  新版将正文拆为事实概述、工作流程比较推断、核查条件三种职责。
- 报告 `summary_json.content_json.presentation` 可容纳新阅读结构和论点审计。
  不需要 SQL 迁移；旧报告保留其存储内容，只有新生成报告采用 v2 阅读结构。
  存储生成器版本升级为 `competitive-report-v3`。
- 历史确认事实中的套餐权益不等于结构化价格。写作不得从原始价格引用
  恢复已拒绝候选、补写币种或其他计费条件，也不得把缺失价格转换为排序。

## 实现与可信边界

`domain/report_writing.py` 是纯函数写作层，无数据库、HTTP 或 Provider 配置。
`comparison_presentation.reading_view` 作为兼容入口保留。

1. 原始 matrix、facts、evidence、历史 conclusions 不变。
2. 新增 `writing.claims`：每条论点具有类型、正文、Fact / Finding / Evidence ID。
   事实和分析推断必须有确认事实；验证引用存在、产品归属、来源 URL、原文、
   时间、确认状态及置信度。研究范围、缺口、规则边界、后续问题单独标记。
3. 中文表达使用产品无关的有限词表；规则同时匹配确认事实字段和对应引用。
   `writing.phrases` 保存规则、字段名、字段片段和原始引用片段。
   对匹配句中的否定表达采取保守拒绝。未知措辞不猜译，原文仍可查看。
   这是有限规则，不是通用语言蕴含检测器，不声称能理解任意否定或复杂语义。
4. 共同能力沿用既有采集日期、冲突及可用性边界。共享同一事实的类别在差异
   章节合并；矩阵展示操作内容，差异解释流程环节，结论提出可执行的核查条件。
   现有 synthesis 仅可优先排列与当前合法比较一致的事实，不可注入正文。
5. `writing_request` / `validate_writing` 是可注入编辑器的最小契约。
   允许重排服务器已生成的分析论点，要求文档摘要、完整集合、原文及引用精确一致。
   正确 ID 并不能证明新增断言，因此自由转述、价格、优势或任意新正文均拒绝。
   输出错误或异常回退到规则报告，异常正文不会进入报告。
   未注册真实 DeepSeek 写作适配器，也未新增真实调用入口。
6. `presentation` 同时驱动正式页面、Chat-first Workspace 与 Markdown。
   页面点击引用展开对应原文；Markdown 使用来源锚点及链接。
   技术 ID、论点与原始事实在审计区。正式报告页避免重复展示两份执行摘要。

## 离线回放与验证

`scripts/replay_report_writing.py` 读取可信的既有分析 JSON 导出，在一个**新目录**
生成中英文 Markdown、阅读 JSON 和输入哈希验证记录。输出目录存在时拒绝覆盖。
不连接数据库，不生成新 Agent run，不修改原始导出或历史报告。
真实回放材料和报告样例放在本地忽略的 `build/` 中，不提交到仓库。

新增合成测试覆盖双语正文、片段证据、跨章节去重、否定句、冲突事实、缺失来源、
错误产品归属、错误 Evidence ID、跨事实错配、虚构价格、无根据优势、无来源断言、
重复/缺漏论点、过期文档摘要和异常回退。Node 测试执行生产渲染函数，核对正文、
表格、引用点击、审计折叠和来源文本安全；这是 DOM 行为验证，不是视觉截图验收。
既有 MySQL 集成测试仍使用可丢弃 `_test` 数据库与注入 Provider。

验证记录：修改前基线 598 passed；最终全部非付费回归 629 passed，新增 31 项。
两份生产 JavaScript 均通过 Node 语法检查；唯一警告为既有 Starlette/httpx 弃用提示。
没有新增数据库迁移、付费调用或完整真实 Agent E2E。

离线验证证明工程契约与规则输出，不证明模型自由写作的准确性、流畅性或泛化能力。
中文正文已不再依赖大段英文描述，但有限词表无法完整转述所有产品细节。
未覆盖信息仍保留在原始事实与引用中，未假装完成通用中文写作。

## 下一次最小真实写作验收方案（待单独授权）

这是一项独立实验方案，本阶段不执行，也不自动续跑完整 Agent。

- 使用已经验证的同一份 matrix 和阅读文档；只取两组比较及其证据。
  不搜索、不抓取、不重新提取、不写数据库，不覆盖历史文件。
- 单次 DeepSeek 写作请求，预计输入 4,000–6,000 tokens、输出 1,000–1,500 tokens；
  硬上限输入 8,000、输出 2,000 tokens、1 次请求、0 次自动重试。
- 费用按执行前核实的实际模型费率计算。可接受费率上限为输入 $1 / 百万 tokens、
  输出 $4 / 百万 tokens；这是实验的费率限制，**不是当前官方价格声明**。
  在该上限下预计 $0.008–$0.012，最坏 $0.016；总预算硬限制 $0.02。
  调用前按最坏输入/输出预留预算；费率未知、超限或 token 超限时停止，等待用户决策。
- 若评估当前受限编辑器，只能验证重排协议，不能称为自然中文写作验收。
  若评估自由转述，输出只能保存为隔离的、未验证候选，不能进入正式报告。
  现有校验器会拒绝这些自由正文；不得临时放宽它来让实验通过。
- 人工逐条核对候选句与确认事实/证据，检查语义、限定条件和翻译遗漏；价格、优势、
  用户适配断言零新增，引用必须 100% 正确。中文可读性、章节分工和重复程度单独评估。
  发现一条无依据的实质断言即不通过。只有独立审阅后的表达才能作为后续规则候选，
  再通过离线回归；不允许模型自己声明“有依据”后直接发布。
